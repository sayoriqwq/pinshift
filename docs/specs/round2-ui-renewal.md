# 第二轮：续签、收藏与维护界面

## 范围与设计依据

本规格汇总用户已确认的第二轮需求。视觉与交互以 Grok 的 `pinshift-round2-ui.html` 迭代 2 为参考；原始设计位于维护者现有工作区 `docs/design/`，不是可直接移植的业务实现。沿用已落地主业务设计，提取对象与操作就近、清晰空间层级、原生反馈、维护入口精简和证据深入的理念。

不得将设计稿的演示控制台、场景切换器、示例标记、设计解释、写给维护者的评审文案或固定演示数据放进正式 App。不得从计时演示推断真实状态。手机观测不保证物理位置，也不等于 Mac 回执。原型与 CONTEXT/ADR 冲突时以既定业务约束和本规格为准。

不包含 Issue #31 的快捷指令、远程启动或唤醒 Mac；本轮续签要求已配对的 Simulation Controller 正在运行。不新增常驻服务、云服务、多设备管理或自动续签计划。

## 用户可见行为

### 语言

- 中文 → 英文 → 中文连续切换立即更新当前页面、已打开的更多及之后打开的弹窗和选点界面。
- 保留当前 Selected Location、Saved Locations、Controller Link 和进行中的操作；不得通过销毁整个业务模型来刷新文案。
- 使用本地化 key 与事实状态，避免将已翻译文本当持久业务状态。用户自定义收藏名不随语言变换。

### 收藏与地图交互

- 沿用地图、搜索、快捷收藏和底部地点操作卡的既有设计语言。
- 地点操作卡的收藏控件呈现未收藏/已收藏状态。未收藏可命名保存，已收藏提供就地重命名、取消收藏；快捷收藏可提供原生上下文菜单作为补充，不把长按作为唯一可发现入口。
- 删除/改名复用已有持久化与错误处理，不能影响当前选点或正在执行的 Temporary Simulation。点收藏只选点，不 Apply。旧坐标收藏迁移能力不得丢失。
- 保留清晰的待应用位置、活动模拟与最新观测区分，不将观测标注为保证真实 GPS。Apply 与 Clear Now 继续遵守不因历史失败锁住新操作、Clear 始终可达、固定三分钟等规则。

### 更多与续签

- 更多优先提供 App 续签（有效期和动作）、Mac 连接/必要配对恢复、语言以及诊断入口；原有坐标输入/收藏入口是否保留以设计和可用性为准，不创建另一套数据。
- 去掉与当前用户任务无关的常驻 CLI 教程和重复解释；详细状态、观测证据及 GPX 基线放在诊断详情。
- 已连接的可信手机可发起一次续签，复用仓库签名/校验/原位安装流程。手动“立即续签”应真正尝试续期；若只是有效期检查跳过，明确为未续签而非成功。
- 阶段和完成结果来自真实流程，成功至少要求新有效期校验与安装确认。启动失败/需解锁与安装成功分别表达，不把打开 App 当作与安装等价。
- 显示真实可获得的签名有效期，未知就显示未知；不要把任意 Mac 缓存 profile 有效期冒充当前手机安装的签名有效期。
- 续签不阻塞控制器状态、自动解除及后续操作。重复按钮或网络重试不能并发运行多次签名安装；断开/安装导致 App 重启后能查询当前或最近结果，不因为页面关闭而取消 Mac 已接收的工作。
- 不暗中解除模拟；仍由独立的固定截止时间决定自动解除。保留现有收藏、语言与配对数据，不卸载 App。
- 缺少首次配置、需 Apple 登录、手机解锁、签名没有延长、安装未确认、控制器版本不支持等应有诚实可操作的反馈；原始错误留在详细诊断，不能编造自动检测不到的阶段。
- 新增控制器能力只开放给既有认证连接，只允许固定续签操作，设备选择来自控制器配置，不能让客户端指定任意命令、路径或设备。

### 诊断

- 提供可直接查看的详细诊断，至少包括真实当前连接/后端/模拟/手机观测快照，以及本机记录的最近请求、执行回执、失败和观测事件。
- 区分信息来源与时间；断线或陈旧快照不能显示为实时正常。一次请求的相关事件可以按请求标识查看，原始事件和字段可展开。
- 保留导出与清理能力、记录边界和已有隐私清理；导出范围如仅手机本地必须诚实命名，不能声称包含未获取的 Mac 日志。
- 续签过程也进入诊断。详细信息对开发者有价值，但设计评审信息不能混入产品。

## 实现依赖

1. Mac 续签执行/结构化状态 + 已认证 Controller Link 协议扩展，可独立实现。
2. 语言修复、收藏就地操作、更多层级，可独立实现；保留续签界面接入位置。
3. 可读诊断与请求证据视图，可独立实现；与第 2 项集成时接入更多导航。
4. 续签 App 状态与界面接入，依赖 1、2、3。统一兼容性、UI 测试与回归验收。

所有实现使用独立工作树汇入一个 PR，不将维护者未提交的其他变更带入。

## 验证

- Swift Package 测试覆盖续签拒绝未认证请求、固定设备/命令约束、重复请求与并发、阶段/失败/安装确认、控制器响应不被长任务阻塞。复用现有脚本测试夹具，避免触发真实签名和安装。
- 语言采用实际 UI 的连续切换回归；收藏覆盖就地改名/删除后模型与持久化仍一致、选点和模拟不变；诊断验证真实记录能查看/导出且无示例证据。
- 构建 iOS App 并运行相关 Simulator UI 测试，检查中英文、动态字体与原生导航。模拟器/夹具通过不等于真实 Apple 续签通过。
- 真机签名、安装、权限交互若没有执行须明确标记。不得为了测试更改维护者证书、钥匙串、个人 Team 或运行中的真机模拟。
- 最后按 code-review 对基准提交分别进行 Standards 与 Spec 审查，修复问题后将 draft PR 标为 ready。
